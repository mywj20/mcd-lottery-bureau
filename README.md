## 为什么需要它

麦当劳积分抽奖有个奇特的现象：**官方不公示中奖概率**，但奖池是完全公开的。

这意味着市面上大多数"抽奖助手"都面临同一个岔路：

- ❌ 假设等概率 → 编出来的期望值，误导用户
- ❌ 编一个概率 → 更糟，纯属造谣
- ✅ **不猜概率，改算确定值 + 透明情景** → 本项目

## 三个核心数字

### ① 保底回血率 —— 与概率无关

> **实测案例**：24 积分/抽，最低档奖品 = **30 积分**。
> 保底回血率 = 30 ÷ 24 = **125%**。

最差情况都是净赚 6 积分。**此时概率不再重要 —— 任何分布下都不亏。**

当最差档是积分奖时，这个比值是**纯积分比**，与"1 积分值多少钱"的汇率假设完全无关 ——
换任何汇率都是 125%。这是数学结构给出的硬结论，不是估算。

> 注：另一实测案例（最低档为 1 元券、汇率 3.2）保底回血率 82% ——
> 此时结论由情景分析接手（见下）。

### ② 情景分析 —— 透明假设，替代编造概率

不问"期望值是多少"（没有概率算不出），改用**两种明确标注的假设情景**：

| 情景 | 假设 | 用途 |
|---|---|---|
| 悲观 | 90% 概率中最低档 | "相当倒霉"的可信场景 |
| 均分 | 所有档位等概率 | 假想参照（非事实） |

判定分级（按可信度）：
- 最差档 ≥ 成本 → **稳赚不亏**（严格结论，任何分布）
- 悲观情景 ≥ 成本 → **大概率回本**（90% 中最低档都不亏）
- 均分情景 < 成本 → **大概率不值**（除非大奖概率远高于小奖）

数学边界（严格）：任何概率分布的结果都落在 [最差档价值, 最好档价值] 区间内。

### ③ 券的真实价值 —— 因人而异

同样是"立减 3 元券"：

| 用户类型 | 真实价值 | 为什么 |
|---|---|---|
| 每周吃 3 次 | ≈ ¥2.76 | 迟早用掉，券≈现金 |
| 每周吃 0.5 次 | ≈ ¥1.50 | 一半概率用掉，且部分是"为券加单" |
| 已过期未用 | **¥0** | 中了没用掉，等于没中 |

```
券的价值 = 面值 × 你会用掉的概率 − 诱导消费扣减
```

**"诱导消费扣减"是本项目与面值派最大的分野**：券面值再大，若它诱发的是
一笔你本来不会花的钱，那笔支出必须从收益里扣掉。

## 快速开始

### 零配置演示（无需 Token）

```bash
python bureau.py demo
```

### 真实模式

```bash
# 1. 申请 MCP Token：https://open.mcd.cn/mcp

# 2. 配置 Token（二选一）
#    方式一（推荐）：在项目根目录创建 .env 文件
#    MCD_MCP_TOKEN=<你的 Token>
#    （可复制 .env.example 改名；.env 已被 .gitignore 忽略，不会泄露）
#
#    方式二：环境变量
export MCD_MCP_TOKEN=<你的 Token>        # Linux/macOS
set MCD_MCP_TOKEN=<你的 Token>           # Windows

# 3. 运行
python bureau.py check                   # 完整精算报告
python bureau.py luck                    # 欧皇鉴定 + 鉴定卡
python bureau.py check --md report.md    # 导出 Markdown 报告
```

**零第三方依赖**，Python 3.8+ 开箱即用。

## 欧皇鉴定卡

`python bureau.py luck` 生成 600×800 的鉴定卡（SVG，可截图分享）：

| 欧皇 👑 | 欧非守恒 ⚖️ | 非酋 🌧️ |
|---|---|---|
| 净收益 ≥ 0 且券命中率 ≥ 30% | 净收益 ≥ 0 | 净收益 < 0 |

卡片不吹不黑：**赢了给你荣誉，输了给你体面**，顺便把数学结论带上。
过期未用的券价值计 ¥0 —— 这是最容易被自欺的地方。

## 项目结构

```
mcd-lottery-bureau/
├── bureau.py              # CLI 入口
├── bureau/
│   ├── mcp_client.py      # 零依赖 MCP 客户端（唯一触网模块）
│   ├── normalize.py       # MCP 返回 → 可计算结构（含数据陷阱处理）
│   ├── render.py          # 终端报告 / Markdown / 鉴定卡 SVG
│   └── engine/
│       ├── value.py       # 估值模型（使用概率折价 + 诱导消费扣减）
│       └── lottery.py     # 精算引擎（保底回血 / 情景分析 / 欧皇鉴定）
├── examples/              # 示例数据与产物
├── tests/                 # 单元测试（26 个用例）
├── SKILL.md               # Agent Skill 入口
└── MCP_INTEGRATION.md     # MCP 集成说明
```

**设计原则：网络层与计算层严格解耦** —— 所有计算可离线复现、可单元测试。

## 数据陷阱（实测校准，2026-10-12）

本项目的工程价值之一，是把这些坑全部钉死在了代码里：

| # | 陷阱 | 处理 |
|---|---|---|
| 1 | `currentMouthExpirePoint` —— 官方拼写是 **Mouth** 不是 Month | 照抄官方拼写 |
| 2 | `drawPoint` 是字符串 `"24"` 不是数字 | 统一转数值 |
| 3 | 能否抽奖只信 `drawDecision.resourceEligible` | 不得用余额推断 |
| 4 | 奖池**无概率字段** | 用确定值模型，不假设等概率 |
| 5 | 过期券要归零 | `statusText` 含"过期"→ 价值计 0 |
| 6 | 限流 600 次/分钟 | 单次分析仅 4~6 次调用 |

## 边界与合规

- ✅ 只做成本核算与止损建议，**不预测中奖、不鼓励赌博**
- ✅ 所有结论注明数据来源与假设；无法计算时明说，**绝不编造数字**
- ✅ 写操作（`draw-lottery`）必须用户明确确认后才执行
- ⚠️ 非麦当劳官方产品；餐品价格与活动规则以官方渠道为准
